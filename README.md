# 鼠E疫苗_StolenMeat

Targets local Probably Stolen 0.46D (Steam build 26337366). 

## Product path

`HusbandryHelper.CreateButcherCuts` is intercepted before rat cuts are made. The game weight decomposition is preserved. Multiple `raw_meat` units become one native GameItem stack with the original sprite, species tag, prion tag and exact `unitCount`. `small_raw_meat`, `morsel` and `small_morsel` continue as individual native items. The game's drag slot search can merge identical official meat items (`raw_meat`, `small_raw_meat`, `morsel`, `small_morsel`, `fat_meat`, `meat_scrap`, `processed_meat`). Different item IDs or effective item states, including species and prion status, cannot merge. Other items keep their native stack rules. Native item rendering provides the lower-right count badge; amounts from 100 upward use a short `E` label while the underlying count remains exact. Right-clicking a meat stack shows the game's item menu with a `拆分` command; clicking it opens a quantity dialog. The selected quantity goes to a separate slot in the source inventory only if the whole item shape fits, or to the temporary window otherwise. If the temporary window is full, units that cannot fit are discarded by the native unplaced-item path and logged. A window creation error leaves the original source units intact. `ProductBatch` records the source and generated units, and supports future production sources such as breeding.

## Overflow path

Rat butcher cuts are grouped before `OnButcher` invokes the placement callback. For supported meat, an empty native inventory slot can accept the whole prepared stack unless that inventory sets an explicit limit. Placement searches native slots before the temporary window. A native container callback error no longer stops the remaining-item search; units already accepted by that container are not generated again.

`GraphUtils.DestroyIfUnplaced` is observed for explicit capacity contexts (`full`, RAS breeding/hatch/fry growth, and native starter-container overflow). The game's own placement order has already run. When a still-unplaced item reaches this boundary, `OverflowCoordinator` checks store inventory, back/front counters, display, hidden/bazaar storage and trash containers with the native `TryAcceptAll` API. It opens a 10x10 `DirectoryUtils.CreateInventoryWindow` on the first qualifying overflow event even if this extended search finds a native container for that item. Remaining units enter the window. If it cannot accept all units, the native discard path handles the remainder. The window is not registered as a reopenable game container. Its close button clears and destroys every item still inside. `OnWakingUpEarly` clears and closes it at the next day; leaving the store and normal save loading do not trigger cleanup. Disabling the Mod also cleans up its window. A later independent overflow may create a fresh window.

## Diagnostics and limits

All important interceptions, placements, discards, splits and cleanup operations log UTC timestamps through the game's `ModLog`. This prototype does not intercept unrelated intentional item destruction or load-time item rejection. `GameItem.GetSplitItem()` prepares splits on isolated staging items, while calculation-only proxies use a separate copy helper. Both preserve the original item state.

The 0.2.0 runtime log showed the original one-unit empty-slot limit splitting a prepared meat stack during placement; a trashcan UI callback error then discarded the remainder. Version 0.2.1 addressed both paths. The 0.2.1 runtime log showed split meat being accepted by another store container instead of opening the temporary window. Version 0.2.2 routes a split to the temporary window when its source inventory lacks a complete slot, and inserts `拆分` into the native item context menu. It passes 40 separate simulations. The new menu and window behavior still need in-game verification.

The mod split dialog calls native `GameItem.GetSplitItem` on an isolated empty staging item, then restores the source item's native state, appearance and runtime callbacks on the result before placement. The actual source is reduced only after the placement or discard outcome is known; the staging-only animal hook suppression does not affect other native items.

## Source-only animal stack extension

Terminology: one rat pile contains rats with the same recorded parents and current age in whole native days, including deferred days. One visible inventory cell may contain several such piles. Unless `cell` is stated explicitly, `rat pile` refers to one parent-and-age group, even when several groups share a cell.

The current source also stacks native `rat` objects, separating live rats and corpses. The versioned item tag stores individual real panels and counted virtual records. Drag merging, the native split path, and the `拆分` menu preserve saved attributes; taking one rat settles or samples its age, hunger and weight. The displayed group tooltip uses quantity-weighted average or expected values and the native lower-right quantity badge. A corpse butcher operation consumes one corpse; a death event separates corpses from a live group. The overcrowding calculation counts actual units inside stacks. `ItemStackPolicy.AllAnimalsEnabled` is the default-off switch for future husbandry species.

Growth uses the native weight-change function for both branches. For each parent-and-age virtual pile, the saved cumulative hunger probability chooses between the ordinary virtual panel and an alternative branch. Below 400 hunger, the alternative uses the native starvation tag; at or above 400 it uses the day's unfed hunger capped at 399. Expected branch growth is calculated for the whole pile and shared across its members, retaining the existing one-animal-per-pile growth model. Version-9 health history records the probability and conditional daily growth; extracting one rat samples each surviving day before settling its weight. Older payloads lack those daily branch probabilities, so their already-recorded growth remains an expectation. History compression with different lengths or beyond 4,096 days can likewise retain only an expected value. Existing native feces generation uses the rounded expected pile growth.
The official `feces_small`, `feces_medium` and `feces_large` items can stack only with matching item state and type; the existing count display and split menu also apply. Native rat growth produces feces at the game's growth threshold and uses post-growth weight to select the native size. In the virtual path, each parent-and-age pile performs one shared growth and feces event; native and virtual placement prefer an existing compatible stack and use the temporary overflow window when needed. Native chemical dissolution consumes one stack unit at a time, preserving each unit's chemical contents.
Native mating stores a unique mother/father pregnancy key separately from the mother's own parent-group identity. Each newborn receives that key before the game's inherited-genetics step. Different parent groups may share one visible rat stack, but every virtual record retains its own parent key; compression never combines records with different parent keys or current ages. Legacy records already compressed across ages remain opaque and cannot recover their original age boundaries. Multi-rat splitting takes a single parent-and-age group when one has enough units, including nonadjacent records. A one-rat split takes the latest inserted virtual parent group, while previously extracted real rats retain their established top priority. Mixed visible stacks use a `mixed` group marker. A merge is rejected when its distinct records cannot fit without crossing parent or age boundaries. Existing rats without a recorded parent group continue to use the legacy empty key. A legacy record already compressed across different parents cannot recover its original individual boundaries; it remains an opaque statistical record and is not merged further.

While a live group remains stacked, its daily path applies the native `HandleHunger` rule to the virtual panel. `AnimalGroupFeeding` then counts reachable dispenser kcal as `A` and eligible loose item units as `B`, using the native dispenser target (85% by default) and loose-food threshold (75%). It calculates `P(A)=min(1,A/(n*dispenserGap))`, `P(B)=min(1,B/((1-P(A))*n*looseGap))`, and tonight's unfed rate `S1=(1-P(A))*(1-P(B))`. Actual feeder energy is measured from the difference in stored energy before and after the native draw; consumed loose-food units contribute their native calorie values. The virtual hunger gain per rat is the combined energy difference divided by the number of rats, capped at the native maximum hunger. Even when the feeder rate caps at 100% and draws only one native dispenser gap, the group receives only the energy actually removed. Each pile saves only the cross-night total rate `S_next=S_previous*S1`; tonight's rate is an internal day-step value used for `floor(n*S1)` visible splitting and is omitted from version-8 records. Rounded fractional probability remains saved in the resulting cohorts. Extracting one virtual rat samples the saved total rate to decide whether its individual panel has the unfed state. The custom unfed-cohort tag is distinct from native `ANIMAL_IS_STARVING_TAG`, which is set only when hunger reaches zero. An unfed cohort normally skips later feeding, but a cohort with the native starvation tag is offered food on the next day. Native starvation then clears the tag if its hunger rises above zero, or turns a second consecutive zero-hunger cohort into a native corpse stack. If feeding is partial, only the remaining zero-hunger share dies. A single rat left in either virtual pile stays virtual until it is extracted. When the original container is full, the hungry pile uses the temporary window. If that window is full too, both cohorts remain recorded in the original pile rather than losing rats.

The normal fed pile also tracks a saved prion probability `R`. For each reachable dispenser, `Q` is the pre-draw proportion of rat-meat kcal in the native proportional feed categories; the rate uses a drawn-kcal-weighted average of marked dispensers' `Q`, so `R(A)=P(A)*Q` for prion-marked rat-meat storage. For loose food, `T` counts all eligible item units, `T1` counts rat-meat units with the native prion tag, and `T2` counts rat-meat units without it. With native current immunity `I` rounded as the game's cannibalism check does, `R(B)=P(B)*(1-P(A))*(T1/T+T2/T*(100-I)/100)`. The fed pile adds `R(A)+R(B)` to its prior `R`, capped at 100%; the hungry pile keeps its previous value. Taking one virtual rat samples the native `ANIMAL_PRION_TAG` from `R` and applies the game's growth, immunity and longevity allele-A bonus changes once. Compressed mixed real panels preserve prion probability separately from unrelated numeric variance.

The virtual pile's hygiene step computes the native two-roll contamination probability without drawing individual disease outcomes. The saved disease rate `D` represents the sick share of one parent-and-age pile. Its members use a shared, quantity-weighted immunity value. With today's native infection probability `p`, the sick share before recovery is `D_hit=D+(1-D)*p`. The pile's health is updated as one panel: apply native immunity regeneration or loss once, then subtract native disease damage multiplied by `D_hit`, clamping between zero and the current native maximum. That maximum comes from `GeneticHelper.GetCurrentStat(..., "ANIMAL_MAX_HEALTH_TAG")`; it is not fixed at 100. Saved animal records and real-animal captures also correct health outside their individual native bounds. Native immunity recovery applies afterward, giving `D_next=D_hit*(1-cureRate)`; it does not undo today's damage. If the shared virtual health reaches zero, every virtual rat in that pile becomes a native corpse regardless of `D`; dead rats skip that day's later crowding and growth. Otherwise, extracting one rat still replays its saved health steps in native individual order and may yield a dead individual even while the group panel remains positive. The per-day risk, regeneration, damage, health maximum, recovery chance, hunger, prion rate and virtual growth remain in the version-9 animal payload; old versions remain readable. The pile's health is therefore a shared virtual value rather than the arithmetic mean of every possible extracted health panel near zero. Already extracted real rats normally make native daily disease and health checks; when only one virtual pile is present in their cell, they also die if that pile's shared virtual health reaches zero. In a mixed cell their individual health is checked separately because their pile membership is not recorded. Histories of different lengths merged under the existing record cap fall back to their current group panel; histories longer than 4,096 days fold the oldest day into that panel. Those two rare compaction paths are statistical approximations.

Each virtual parent-and-age pile updates its separate `STOLEN_MEAT_VIRTUAL_FERTILITY` display value after hygiene and overcrowding, before growth. Overall hunger and the saved cross-night hunger rate are quantity-weighted within that pile. Below 200 hunger the previous coefficient is `0.002*S*(P-1)+0.4`; at or above 200 it is `0.4*P`, with native old-age, crowding and disease terms added. Native genetic current fertility loses the expressed genetic fertility multiplied by this coefficient, with the native zero floor. `P` is the saved cumulative hunger rate. Separate parent-and-age groups and fed/unfed cohorts keep separate hunger inputs; real extracted rats use the native fertility tag and native update. Existing records written by earlier development code may already have had their native fertility tag overwritten and cannot reconstruct that prior value automatically.

Small virtual groups retain individual records; large homogeneous groups use a counted record. The target is at most 128 real panels per container. Excess real panels are compressed within their own pile first; a compatible native merge can then combine separate single-rat items. Paired panels become virtual records with numeric means and variances; discrete string, Boolean, sprite, custom-text and item-value attributes retain marginal choices rather than becoming fixed to the first panel. Extracting one samples a new real panel. An odd final excess panel becomes virtual with its exact numeric values. The 4,096-record and 32 MB payload limits still apply to all saved records. Native-incompatible single-rat items are left separate and logged rather than merged across the game's rules. Existing standalone items are counted at day end, but native item merging is only attempted during a stack merge, when changing the container contents is safe. Animal stacks can hold up to `Int32.MaxValue` units without expanding that many objects. The current source passes 161 isolated simulations. It has not been packaged into the 0.2.2 release or tested in the running game.

`BinomialSampler` takes its success probability from each caller and contains the shared exact inner/outer-ring draw and bounded Box-Muller approximation; `DoseSplitPreparation` supplies the existing drug-specific thresholds and two-rat rule. `AnimalSexSampler` supplies the native 50% female probability for animals whose sex is not yet known. The sex sampler is available as an isolated building block and is not yet wired into mating or births. Its normal switch uses the same skew threshold with a minimum of 128 trials, since the skew expression vanishes at 50% even for tiny samples. Normal values use the previously requested floor, which produces about a half-unit downward bias away from boundaries. Known individual sexes must not be redrawn.
`AnimalCellIndex` indexes one stack item by cell ID, parent-and-age pile keys and saved individual IDs; its snapshot rejects changed tags, counts or parent inventory. `AnimalInspectionNavigation` pages virtual piles and saved individuals without materializing virtual animals. The native item context menu offers an animal-inspection command that opens a CustomUI window with fixed mode and page buttons around a scrollable details area. A native singleton can be inspected, and the total includes virtual and real units. Individual details use the native animal tooltip, including the native gene-scanner condition; the scanner is otherwise unchanged. Virtual details use recorded values only, and sex/pregnancy/neutering counts are marked unavailable when the saved record cannot establish them exactly. The new population, pregnancy and drug data models remain disconnected, so their unsaved values are not displayed. Runtime layout and game hooks have not yet been tested in the running game.
`AnimalPilePanel` is an isolated one-pile data container holding virtual records and exact `AnimalPopulationCounts`. `AnimalPilePanelFactory` accepts only live virtual records with known matching parent identity and age, and verifies the population total. `AnimalPopulationOperations` contains newborn sampling, procedures, splitting and serialization, separate from the data container. The panel is not yet integrated into the existing animal payload or display, and its counts are not synchronized with game mutations. `AnimalProcedureDialog` is isolated preparation for the centered procedure selector. Their counts and single-animal draws are tested but not yet attached to actual animal payloads, newborn generation, item splitting, the wire-cutter hook or native surgery; no active gameplay behavior is claimed. The isolated multi-animal split floors sex and then sex-specific neutering and pregnancy counts, preserving total and marginal counts; it may reassign the pregnancy/neutering overlap for virtual animals when necessary, as requested. Previously extracted real animals must keep their individual states when the model is integrated. The menu's female-only choice excludes pregnant females; the any-animal choice includes them. Native wire cutters neuter pregnant animals without miscarriage; native surgery on a pregnant animal causes miscarriage without additionally neutering it.
`IAnimalMatingCalculator` reserves a per-pile interface returning female counts for one, two and three matings, alongside internal ratios and a 64-bit total mating count. The production algorithm remains unspecified and unconnected. Tests only use one quarter of all females for each of the three groups, rounded down; the remainder is unpaired. This placeholder does not invoke mating or births.
`AnimalBirthCalculator` accepts one pile's one/two/three-mating distribution, an already determined effective native per-mating fertility percent and the caller-supplied average litter size. Native per-mating success uses the integer percentage, and the calculator uses independent-roll success probabilities for each mating group. It retains expected pregnancies and expected offspring as finite doubles without rounding or expanding individuals. The calculator does not decide parent selection or calculate the average litter size, nor does it mark pregnancies or generate births.
`TimedStateTable` is a reusable counted remaining-days table. The existing `DoseSchedule` uses it for active doses while keeping its own pending-dose rules. `PregnancySchedule` uses the same table for a single parent group; its isolated model retains parent identity, native progress and counted remaining days, and can serialize and restore itself. It is preparation only: pregnancy schedules are not yet attached to animal payloads, the daily pregnancy/miscarriage path, mating or newborn spawning. The game normally reads each animal's gestation-period tag, checks starvation miscarriage, and draws the native litter and inherited genetics; the batch-birth distribution and genetics policy is awaiting the user's design. Ordinary unstacked animals continue through the native game path.
The source contains an isolated drug model: native steroid and immunity effects are added as bonus rates and then applied as a multiplier to a separately supplied ordinary panel. `VirtualDrugPile` immediately updates the effective value, stores active and pending schedules, and preserves remaining days during its own split and merge operations. Only virtual rats are intended to share this state; previously extracted real rats retain separate effects. The model is not yet connected to the game's injection hook, visible tooltip, animal payload, automatic hunger/death splits or native item split/merge paths; it must not be treated as active in the game. Integration requires a shared transaction so a preview, partial placement or failed save cannot duplicate or lose drug doses. Drug effects use double precision in the isolated model so a single injection is not rounded away at `Int32.MaxValue` rats.
## Panel fidelity audit

The visible group tooltip labels age, weight, hunger, base growth, base fertility and current fertility as expected averages; health is labeled as the group panel. A single extracted rat gets a native item panel, with saved individual tags where available and deferred health, prion, hunger and growth resolved at extraction. This is not yet a complete native lifecycle replay: the stacked-day path bypasses native old-age death, movement, mating, pregnancy progress and ingester updates. Previously starving virtual rats now resolve native death before their own hygiene, crowding and growth checks, while physical corpse placement still happens at the end of this mod's day step. The container-wide crowding snapshot is taken before starvation, so it can still include rats that die that day. Large-batch crowding deaths currently use a representative expected corpse panel and clear deferred individual history. Statistical real-panel compression stores marginal numeric and discrete distributions, so correlations such as a particular sex with a particular sprite or gene combination are not guaranteed. Different-length health-history merging and the 4,096-day history limit also use expectations. These cases need further design before claiming that every extracted animal has a fully native-consistent real panel.

The reusable `AnimalPopulationPolicy` selects unified calculation when there are at least 32 rats and virtual records are not a minority, or whenever the container has more than 128 rats. One container death budget uses `a(n-H_n)`; `H_n` is summed exactly up to 100,000 and approximated for larger counts. The budget is divided by virtual/real unit counts. Virtual deaths are first rounded across visible cells, then compressed virtual deaths are distributed across each cell's distinct parent-and-age piles in proportion to population; this two-stage rounding is not identical to global pile-level rounding. They form counted native corpse stacks. Real deaths take the globally lightest indexed panels, preserving those panels in corpse records. Smaller containers outside that policy use the native 5%/15% attack roll per rat. Same-pile weight comparisons use a 50% roll; different piles use virtual or real panel weights. Hygiene uses the game's contamination thresholds, with disease outcomes deferred for virtual rats. Every check and pile summary is logged in bounded batches. The unified budget is a requested approximation of native per-rat rolls and needs verification in the running game.

All native stacks are bounded by `Int32.MaxValue` units. An actual merge that would exceed the limit retains exactly `2^23-1` units in its target and deletes the excess participating units. Animal overflow deletes virtual records first, then real panels from the bottom. A partial merge preserves source units that were outside the requested transfer. Mod-generated meat counts are capped at `Int32.MaxValue` before calling the native count setter.
